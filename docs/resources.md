## Glossary

<!-- TODO: Mari — extend as topics are finalised -->

| Term | Meaning |
|------|---------|
| **LLM** | Large language model: a model trained to predict the next token of text. |
| **Token** | A chunk of text (often part of a word) that a model reads and writes; also the unit of API billing. |
| **Context window** | The maximum number of tokens a model can consider in one request. |
| **Embedding** | A list of numbers representing the meaning of a piece of text; similar texts get nearby vectors. |
| **Vector store** | A database that finds the embeddings closest to a query embedding. |
| **RAG** | Retrieval-augmented generation: fetch relevant text first, then ask the LLM to answer using it. |
| **Chunking** | Splitting a long document into smaller passages before embedding them. |
| **Agent** | An LLM in a loop that decides which tools to call to reach a goal. |
| **Tool** | A function the agent may call, such as "search the paper". |
| **Memory** | State the agent keeps between turns, e.g. conversation history. |
| **Guardrail** | A check on inputs or outputs that blocks unsafe or off-topic behaviour. |
| **Rate limit** | A cap on requests or tokens per minute set by the API provider. |
